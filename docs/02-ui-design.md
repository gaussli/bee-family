## 1. 设计理念

> **一张被暖光晒过的纸质相册。**

三条互相支撑的原则：

| 原则 | 含义 | 落到像素上 |
| --- | --- | --- |
| **暖而不甜** | 主色是蜂蜜金而非糖果粉；靠留白和纸感撑起温度，不靠圆润卡通 | 页面底色 `#FBF7F1`；圆角最大 20px；不使用渐变彩虹、不使用描边小图标填充 |
| **照片是主角** | 所有装饰必须让位给照片。UI 元素"退后半步" | 卡片无边框仅用极淡阴影；导航为暖白底、激活项才用蜜金；照片单元 hover 才出现蒙层 |
| **有手工感** | 像手写标注的纸相册：衬线数字、微微的纸张颗粒、偶尔的蜂巢纹样 | 大数字用衬线体；页面底 3% 噪点；蜂巢纹样只出现在空状态与 Logo |

**反面清单（明确禁止）**：糖果色渐变、玻璃拟态、彩虹描边、Emoji 当图标、大圆角气泡对话、动画超过 400ms。

### 2.7 字体

```css
--font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB",
             "Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", sans-serif;
--font-display: "Songti SC", "Noto Serif SC", "Source Han Serif SC", Georgia,
                "Times New Roman", serif;
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace;
```

- `--font-sans`：正文、控件、导航 —— 全部。
- `--font-display`：**仅**用于 ① 大数字（照片数、天数、身高值）② 登录页品牌标题 ③ 时间轴的年份数字。用来制造"纸质相册上印刷体数字"的质感。
- 所有数字使用 `font-variant-numeric: tabular-nums;`，避免统计数字跳动。

## 3. 蜂巢母题实现规范

### 3.1 形状定义

**尖顶六边形（pointy-top）** —— 主用形态，宽 : 高 = `0.866 : 1`

```css
.bee-hex {
  aspect-ratio: 1 / 1.1547;      /* = 1 / (2/√3) */
  clip-path: polygon(50% 0%, 100% 25%, 100% 75%, 50% 100%, 0% 75%, 0% 25%);
}
```

**平顶六边形（flat-top）** —— 仅用于横向排列的装饰纹样

```css
.bee-hex--flat {
  aspect-ratio: 1.1547 / 1;
  clip-path: polygon(25% 0%, 75% 0%, 100% 50%, 75% 100%, 25% 100%, 0% 50%);
}
```

**带描边的六边形**（`clip-path` 无法直接描边，用双层嵌套）

```css
.bee-hex-ring {           /* 外层：描边色 */
  background: var(--honey-500);
  padding: 2px;           /* 描边宽度 */
  clip-path: polygon(50% 0%, 100% 25%, 100% 75%, 50% 100%, 0% 75%, 0% 25%);
}
.bee-hex-ring > .bee-hex-inner {
  width: 100%; height: 100%; display: block; object-fit: cover;
  background: var(--bg-surface);
  clip-path: polygon(50% 0%, 100% 25%, 100% 75%, 50% 100%, 0% 75%, 0% 25%);
}
```

**蜂巢铺排公式**（尖顶，行内 6 个，行间错位）

```
单元格宽 = W，高 = W / 0.866 = 1.1547W
行内水平间距 = 0（紧贴）
第 2 行整体左移 W/2，上移 (1.1547W - 0.25 × 1.1547W) = 0.866W
即：.row:nth-child(even) { margin-left: calc(W / 2); margin-top: -0.288W; }
```

### 3.2 使用位置（明确取舍）

| 位置 | 是否采用 | 说明 |
| --- | --- | --- |
| **品牌 Logo** | ✅ 采用 | 单个尖顶六边形，内嵌简笔蜜蜂或蜜滴；尺寸 32×37（侧栏）、24×28（移动端） |
| **头像框** | ✅ 采用 | 宝宝头像使用六边形（尖顶），相框描边 2px `--honey-200`；**成人成员头像使用圆形**（区分成人与孩子，圆形更中性） |
| **加载动画** | ✅ 采用 | 7 个微型六边形（中心 1 + 环绕 6），逐个 0.9s 循环透明度 0.25→1；单格 8×9px，间距 2px |
| **里程碑徽章** | ✅ 采用 | 40×46 六边形，蜜金渐变底，内嵌白色图标 |
| **空状态底纹** | ✅ 采用 | 背景铺 3×4 蜂巢网格，填充 `--honey-50`，不透明度 100%，作为插画的底 |
| **页面装饰纹样** | ⚠️ 极少量 | 仅登录页左侧品牌区的右下角，4 个六边形组，透明度 8% |
| **相册封面网格** | ❌ 不采用 | 六边形会裁掉照片四角主体（人脸常在边缘）；且与 1:1 方形网格混排会让网格节奏崩坏 |
| **照片网格单元** | ❌ 不采用 | 同上；照片墙必须是正方形（对齐率 100%，瀑布流不做） |
| **按钮 / 卡片形状** | ❌ 不采用 | 会牺牲可用性（可点击面积、文字排版） |
| **相册卡封面裁切** | ❌ 不采用 | 用 4:3 圆角矩形；仅在**卡片左上角**放一个 20×23 的六边形小徽章藏"照片数" |

> **决策**：蜂巢母题在本产品中的角色是**"徽章与纹理"**，不是**"容器与网格"**。一旦它开始决定照片被裁成什么形状，就停止了。

### 4.12 TimelineItem（时间轴条目）★核心组件

**结论：单列（非左右交错）。**

| 理由 | 说明 |
| --- | --- |
| 1. 阅读方向一致 | 左右交错会让眼睛每屏做一次 Z 字跳，长时间浏览疲劳 |
| 2. 照片比例不定 | 交错的奇数项需要不同高度来平衡视觉，导致网格节奏混乱 |
| 3. 移动端复用 | 单列在 <768 时只需隐藏时间脊柱即可完美降级，交错布局无法降级 |
| 4. 扫描效率 | 家庭相册是"快速滑过"，单列保证图片左边缘对齐，滑动时视觉焦点稳定 |

| 项 | 规格 |
| --- | --- |
| 列表容器 | `max-width: 880px` 居中（不是 1200，单列过宽会显得照片小且散） |
| 时间脊柱 | 左侧竖线 1px `--warm-300`，`left: 79px`（= 时间列宽 64px + 间距 16px - 0.5px） |
| 左侧时间列 | 宽 64px，右对齐，显示「10月 24」「周五」两行，字号 12/500 `--text-tertiary` 与 12/400 |
| 节点圆点 | 10×10 圆形，背景 `--bg-page`，边框 2px `--honey-500`；里程碑条目圆点改为六边形 12×14 填充 `--accent-coral` |
| 条目间距 | `--sp-8`（32px）；同一月份内条目间距 24px |
| 月份分组标题 | 高 44px，`position: sticky; top: 64px;` 背景 `rgba(251,247,241,.92)` + blur；内容「2026 年 10 月」用 `--font-display` 20/600 + 右侧 1px 横线延伸 |
| 照片条目 | 卡片内 padding 0，图片 `aspect-ratio: 4/3` 裁切（统一节奏，点击进灯箱看原比例），`--r-lg`，下方 12px 内边距显示标题/地点（有则显示） |
| 里程碑条目 | 卡片 padding `--sp-5`，左侧 3px `--accent-coral` 竖条；顶部六边形徽章 32×37 + 标题 `--fs-h4`；描述 14/400 `--text-secondary`；右侧可选 64×64 缩略图（点击开灯箱） |
| hover | 卡片 `--shadow-sm → --shadow-md`，图片 `scale(1.02)` |
| 进入动画 | 首屏 5 条依次 `opacity 0→1, translateY(8px)→0`，步长 40ms，总计 480ms |

## 6. 交互细节

### 6.1 上传全流程

| 阶段 | 表现 |
| --- | --- |
| 触发 | ① 点击「上传照片」→ 系统文件选择框（`multiple`）；② 拖拽文件到相册详情页任意位置 → 全屏虚线遮罩；③ 粘贴（P1） |
| 预校验 | 前端立即校验扩展名（jpg/jpeg/png/webp）与大小（≤20MB），不合格文件**不进入队列**，聚合为一条 Toast warning：「3 个文件超过 20MB，已跳过」 |
| 队列 UI | 右下角浮层卡片，宽 360，最多显示 4 条，其余折叠为「还有 12 张」；每条含 40×40 缩略图（`URL.createObjectURL`）+ 文件名 + 进度条 |
| 进度 | 单条进度条高 3px，`--honey-500`，宽度动画 `--dur-fast linear`；顶部汇总「已完成 32 / 100 · 12.4 MB/s」 |
| 并发 | 3 路并行；每张分片或整包上传由架构决定，前端仅展示 |
| 失败 | 该条变 `--color-danger-bg` 底 + 「重试」文字按钮；汇总区出现「全部重试」 |
| 完成 | 全部成功 → 卡片收起动画 320ms + Toast success「已上传 100 张照片」；列表原地插入新照片（不做整页刷新） |
| 取消 | 卡片右上 ✕ → 确认「取消会中断正在上传的 8 张」 |
| 可关闭 | 上传中卡片不可点击穿透；用户可点「后台继续」收起为右下角迷你进度环 40×40 |

### 6.2 拖拽上传区

- 触发阈值：`dragenter` 计数 > 0 时显示；`dragleave` 到窗口外才隐藏（用计数器避免子元素抖动）。
- 视觉：全屏固定层，内缩 16px，2px `dashed --honey-400`，圆角 `--r-lg`，背景 `rgba(255,239,210,.72)` + `backdrop-filter: blur(4px)`；中央 48px 上传图标（蜜金）+ 「松开即可上传到《相册名》」`--fs-h3`。
- 动画：`opacity 0→1` 160ms。
- 仅在接受文件的页面启用（相册详情、时间轴）。

### 6.3 图片懒加载与骨架

| 项 | 规格 |
| --- | --- |
| 懒加载 | `loading="lazy"` + `IntersectionObserver`（`rootMargin: '200px'`）双保险；未进入视口时 `src` 为空 |
| 占位 | 单元容器 `--warm-100`；图片 `opacity: 0`，`onload` 后 300ms 淡入 |
| 缩略图策略 | 网格用 480px 版本（约 40–80KB）；灯箱用 1600px 版本 |
| 长列表优化 | 相册详情对超出 200 项的单元加 `content-visibility: auto; contain-intrinsic-size: 200px` |
| 骨架 | 首屏用骨架；已加载过的区域切回不闪骨架（用 `Map` 缓存已加载状态） |

### 6.4 状态样式总表

| 状态 | 规格 |
| --- | --- |
| `hover` | 颜色加深一档 / 背景浮出 `--honey-50` / 位移 `-2px`（仅卡片）；过渡 `--dur-fast ~ --dur-base` |
| `active`（按下） | `transform: scale(0.98)`，`--dur-fast`；按钮背景再加深一档 |
| `focus-visible` | `outline: 2px solid var(--honey-500); outline-offset: 2px;` 或 `box-shadow: var(--shadow-focus)`；**禁止** `outline: none` |
| `disabled` | `opacity: .45`，`cursor: not-allowed`，移除所有 hover 效果 |
| `selected` | 背景 `--honey-100`，文字 `--text-brand`，左侧 3px 蜜金竖条 |
| `dragging` | `opacity: .6` + `--shadow-lg` |

### 6.5 键盘可达性

| 场景 | 快捷键 |
| --- | --- |
| 打开全局搜索 | `/` 或 `⌘K` / `Ctrl+K` |
| 关闭浮层（灯箱/模态/下拉） | `Esc` |
| 灯箱上一张 / 下一张 | `←` / `→` |
| 灯箱切换信息栏 | `I` |
| 灯箱全屏（预留） | `F` |
| 搜索结果上下移动 | `↑` / `↓`，`Enter` 打开 |
| 相册网格内移动 | `←` `→` `↑` `↓`（roving tabindex） |
| 下拉/模态内 Tab | 焦点陷阱循环 |

**硬性要求**：所有可交互元素必须是 `<button>`/`<a>`/`<input>` 语义标签；灯箱 `role="dialog" aria-modal="true"`，`aria-label="照片查看器"`；图片 `alt` 取标题，无标题时取「拍摄于 YYYY-MM-DD 的照片」；Toast 容器 `role="status" aria-live="polite"`。

### 6.6 暗色模式取舍

> **结论：本期只做浅色暖调，不实现暗色模式；但 tokens 结构预留。**

| 理由 | 说明 |
| --- | --- |
| 品牌一致性 | 产品的核心体验是"被暖光晒过的纸"，暗色会消解纸感与蜜金主色（蜜金在深底上会变成刺眼的橙） |
| 成本 | 照片类产品做暗色需要重新设计所有照片蒙层、边框、骨架屏，收益低于本期其他 P0 |
| 预留方式 | 所有颜色必须走 token；在 `tokens.css` 中预留 `[data-theme="dark"]` 空区块注释；**禁止**在组件里出现硬编码 hex |
| 照片区域例外 | 灯箱图像区固定使用深底 `#1C1814`（不属于主题色，是"照片衬底"） |

若后续启用暗色，建议方向：`--bg-page: #1E1A16`、`--bg-surface: #272119`、`--bg-elevated: #322A20`、主色降饱和为 `#D99A45`。
